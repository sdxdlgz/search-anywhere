# 用量查询修复验收

## 需求（先于实现及测试）

| ID | 需求 | 验收场景 |
| --- | --- | --- |
| U1 | 用量口径准确 | 官方 key usage=0、limit=null，账号 plan_usage>0，网关有成功调用时，分别显示而非互相覆盖；零/空上限、按量额度、同步时间和失败旧快照可见；本地报告/估算分开 |
| U2 | 单行查询 | 一次只调用该 key 的官方 usage；仅该行进入查询状态，其他行可操作；页面读取不触发官方请求；失败解除状态 |
| U3 | 明确批量查询 | 勾选多个 key 后使用独立批量按钮；只查询所选 ID；空、重复、非法及超过上限的 ID 拒绝；混合成功/失败/不支持逐项返回，成功项不回滚 |
| U4 | 并发和生命周期 | 同 key 单个/批量/后台并发只发一次；失败保留旧数据；同步期间 key 删除或账号归属修改不写入错误归属；定时同步状态可见且维持现有用户配置 |
| U5 | 实际交付 | 针对成功过的真实 Tavily key 只读核对用量；不执行收费搜索；多测试文件、完整构建、浏览器单个/批量/失败/移动布局验证；更新本地服务 |

Tavily 官方接口分别提供 key 与 account 对象，不能用账号总量替换 key 用量，也不能以成功调用次数推导官方计费量。文档：https://docs.tavily.com/documentation/api-reference/endpoint/usage 。

## 实测与实现决定

后续展示调整验收：Q1 每 key 对应独立账号，相同来源备注也应累加，供应商分别汇总；Q2 未同步／未支持不按零额度计算，查询失败保留旧快照并标注，零额度及超额账户剩余不为负；Q3 概览每渠道仅一行，显示已知套餐总额／已用／剩余与覆盖数量，不显示备注分组，桌面及移动布局可用；Q4 完成提示成功后 5 秒、含失败或未支持项时 8 秒自动关闭，新批次不被旧定时器清除，行内错误及重试保留。

编号调整验收：N1 同供应商、同名称前缀跨批次接续最大编号，重复单条导入也不自动重名；N2 其他供应商独立编号，删除中间编号后仍接续现存最大值，长名称生成后保持 100 字符上限；N3 导入失败事务回滚且不占号，不修改现有名称，API 返回与页面展示一致。

Q1–Q4、N1–N3 已完成：49 项自动化测试、生产构建与原生浏览器验收通过。v0.2.2 已在本地运行，现有 12 把 Tavily key 的快照合计为总额度 12,000、已用 436、剩余 11,564 credits；只读取本地快照，没有新增上游调用。

- 只读核对用户成功调用过的一把 Tavily key：本地保存的搜索响应报告 1 credit；重新请求官方 `/usage` 得到 HTTP 200，key usage 与 account plan_usage 均为 0，limit=null，套餐上限 1,000。这不是 JSON 数字解析错误，未证明差异具体由何种上游原因造成。
- 展示分别保留：累计调用、本月上游报告 credits、本月估算、官方 key 用量、账号套餐及按量快照。官方仍为 0 时如实显示，并解释与网关记录的差异，不制造“纠正后的官方余额”。
- 批量在客户端明确组合单项管理接口，3 并发，逐项更新；没有增加长时间等待的批量 HTTP 请求或后台任务队列。
- 单项查询不再触发全页数据重载；测试按钮和用量按钮各有对应行的进行状态。自动同步配置保持原值并可单独暂停。
- 更新服务后再次核验同一把 key，官方 key 与账号用量均已返回 1，与本地报告一致。现有 12 把 Tavily key 全部保留；单次查询后其余 11 把的快照以及全部搜索调用次数均未改变。两次官方返回不同，但未确定其具体更新机制。
- 验收完成：43 项完整自动化测试通过，最终细节调整后的 8 项用量回归和生产构建通过；原生 Playwright 覆盖单个/勾选批量/部分失败重试/独立行状态/页面刷新/自动同步及原有管理流程，桌面和移动布局检查通过。
