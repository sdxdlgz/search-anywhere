# 覆盖优先：需求与验收

当前目标是收集尽可能丰富、可追溯的证据；费用与耗时仍记录，但不参与自动削减渠道。完整仅指本次查询、模式、上游数量及传输限制内返回的资料，不代表全网穷尽。

## 验收场景（先于实现）

| ID | 需求 | 正常、边界、错误与状态转换 |
| --- | --- | --- |
| C1 | 五家供应商适配 | 官方参数/鉴权、Keenable MCP 模式与用量元数据；业务错误不泄漏密钥；未知余额保持未知 |
| C2 | 覆盖预设兼容升级 | 新安装默认覆盖；已有预设/默认值保留；新供应商在旧预设关闭；保存/重启后配置不变 |
| C3 | 收集与展示分离 | 每家请求量不因第一页大小减少；超过一页的结果全部可取；空结果、末页、无效分页参数 |
| C4 | 保留证据 | 同 URL 的不同摘录及同渠道重复摘录保留；原 URL、查询、模式、排名、时间可追溯；过滤及截断可见；跨供应商命中不计独立佐证 |
| C5 | 持久化与隔离 | 分页不新增上游调用；重启仍可读；同名不同 token 不可越权；缓存仍指向原集合；删除/撤销 token 不获得他人资料 |
| C6 | 不完整与读取正文 | 慢/失败渠道保留已完成资料并报告缺口；覆盖正文并行保留多个版本；旧预设正文回退仍兼容；释放所有 key 预留 |
| C7 | 可操作与可观测 | 五家渠道/模式可选；分页与逐来源证据可读；不同供应商 credits 不混算；桌面和移动页面无溢出 |

## 边界

- 不内置第二个模型，不自动宣称核实事实；由调用方拆分问题、补搜反证、比较原文并组织结论。
- 仅规范化 URL 合并，不按相似摘要删除资料。全文与多个摘录保留为不同字段。
- 结果保存在本地 SQLite，保留到管理员自行清理数据；本版不添加自动过期删除。
- 新适配器以官方协议和模拟服务验证；实际账号联调须有可用凭证，未经联调不声称实测质量提升。
