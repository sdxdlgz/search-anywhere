# 历史数据清理

[返回 README](../README.md) · [备份与迁移](backup-migration.md)

搜索结果及读取的网页正文会占用持久化空间。控制台 **备份与迁移 → 历史数据清理** 提供自动策略、存储统计和手动清理。

## 自动清理

默认开启，保留最近 **7 天**。已有实例升级后，如果尚无清理配置，也使用这一默认值。可设置 1–3650 天或关闭自动清理；修改后点击 **保存清理策略**。

服务启动后每分钟检查一次；没有清理记录时，在首次空闲检查执行。之后每次成功清理（含手动操作）间隔 24 小时再次执行。按服务器当前时间计算连续 24 小时的天数，只清理严格早于截止时间的内容。调整天数在下一次计划执行时生效，需要立即应用可手动预览并清理。

有搜索、余额查询、OAuth 网络操作、备份或恢复正在进行时，自动任务顺延到下一次检查。执行失败会回滚本次数据修改并重试，页面显示最近成功时间和当前进程中的错误提示。关闭实例期间不执行，重新启动后会检查是否需要补做。

## 手动清理

1. 选择保留期限，或选择 **清空现有历史内容**。
2. 点击 **预览清理范围**，核对截止时间、搜索日志数、结果集合数、调用明细数及近似内容大小。
3. 保存需要保留的资料，再勾选确认并点击 **确认清理历史内容**。

预览有效期为 10 分钟，只授权清理该预览范围；如果期间数据库发生变化，需要重新预览。空预览不会显示删除确认按钮。清理后，原 `collection_id` 的分页和正文读取返回 404，调用方需要重新搜索。内存搜索缓存同时失效。

## 删除和保留的内容

| 数据 | 处理 |
| --- | --- |
| 过期结果集合、摘录、正文和检索范围信息 | 删除 |
| 过期请求的搜索词、调用方名称、预设名称 | 清空，并从日志列表移除 |
| 过期调用的密钥名称、来源备注、掩码、模式、操作名称、错误和上游明细 | 清空 |
| 计费与统计所需的请求／调用 ID、key ID、时间、状态、耗时、成本、credits、计费来源与余额扣费范围 | 持续保留 |
| 供应商 key、账号备注、登录授权、额度快照、预设、访问凭证和余额校准 | 保留 |
| 已下载的 `.sab`、运维备份、服务器和容器日志 | 不在清理范围 |

精简计费记录用于累计成功次数、本月用量、图表、每日调用上限和 Exa 手动余额扣费。清理历史内容不会重置这些统计，也不会重新增加额度。计费记录仍会随调用缓慢增长；此功能控制大体积搜索内容的保留，并非固定数据库大小上限。

## 存储空间与备份

页面分别显示主数据库、WAL 文件和可复用空闲页面的大小。清理在一个事务中完成；空闲页面供后续写入复用，WAL 尽可能检查点并截短。存在其他数据库读取者时，WAL 截短可能延后。

主数据库文件通常不会立即变小；预览中的内容字节数也不等于实际磁盘释放量。程序不会执行 `VACUUM`：当前 Exa 余额校准依赖调用记录的 SQLite rowid，未经迁移直接重排 rowid 可能影响计费。[SQLite 官方说明](https://www.sqlite.org/lang_vacuum.html)确认 `VACUUM` 可能改变没有显式整数主键的 rowid。请使用内置清理功能，并继续监控磁盘与备份大小。

备份包含清理策略、最近成功执行记录、精简计费记录和未清理内容。恢复旧版备份时，缺失的策略采用默认开启、保留 7 天。长期研究所需的证据，应在到期前导出到独立存档。
