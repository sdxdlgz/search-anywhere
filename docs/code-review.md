# v0.3.0 代码审查记录

审查日期：2026-09-15。范围：HTTP/MCP 权限和输入边界、供应商适配、登录续期与余额口径、调度/缓存、SQLite 持久化、管理页、迁移流程、依赖和容器发布。自动化测试使用模拟上游，不代表重新验证所有供应商的实时可用性。

## 已修正

| 问题 | 影响与处理 |
| --- | --- |
| 仅支持 loopback 可信代理 | Docker 桥接网络中的代理可能使 HTTPS Origin 校验失败、Cookie 不带 Secure。保留旧配置，增加明确跳数和 IP/CIDR 支持；默认仍不信任转发头。 |
| 余额批次可能跨越多个定时周期 | 长批次期间下一次定时器会再次调度。增加批次互斥，并与备份维护状态协调；单 key 查询合并行为保持原样。 |
| 备份迁移可能重新编号调用记录 | Exa 手动余额使用 rowid 游标，重新编号会改变扣减范围。格式显式保留 rowid，并验证有序号空洞时余额不变。 |
| 恢复可能使用过期预览或与续期交错 | 预览绑定文件及目标修改计数；恢复前后校验，维护期间隔离写入，事务失败回滚，完成后清除旧缓存和待授权流程。 |
| 导入与管理 API 的预设校验容易分叉 | 抽出共享 schema；非法模式、超时、默认预设及未知字段在写入前拒绝。 |
| 恢复成功但页面刷新失败时容易误报 | 明确告知“数据已恢复，页面刷新失败”，避免用户误认为整次恢复失败。 |
| 默认测试并发依赖机器核心数 | 固定为 4，降低多临时数据库和密码派生测试同时运行的内存压力。 |
| 镜像可能带入本地数据 | Docker 构建上下文采用源文件白名单；运行镜像只复制产物、生产依赖和管理员口令脚本。备份、数据库和私钥都不进入镜像。 |
| 新服务器的数据文件权限依赖系统默认 umask | 启动时采用 0077，新数据目录 0700；既有目录不强制更改所有权或权限。 |
| 容器测试重启后复用临时端口 | 首次 CI 暴露随机宿主机端口会重新分配；重启后重新读取映射，并保留失败日志。正式 Compose 使用固定端口。 |

## 保留的设计与限制

- 单进程 SQLite、固定供应商地址、有限重试、每 key 并发保护和受限上游响应体适合当前个人部署。暂无证据需要引入 Redis、任务队列或数据库服务。
- API 输入、域名规则、访问凭证权限、原始响应脱敏、登录续期的版本校验及旧数据保留已有回归覆盖。新迁移功能没有提供明文 key 查看接口。
- 官网余额接口可能变化或被浏览器验证阻挡。Exa 官网方案按之前约定暂缓进一步改造，手动估算仍是可用后备；未把模拟测试通过解释为官网实时验证成功。
- Parallel API 请求上限已统一为 20，避免主动触发 40 → 20 的参数警告；历史警告仍保留。网关不自动规划多轮研究，也不根据一次测试判断供应商的普遍优劣。
- 历史内容默认保留 7 天，提供每日自动清理和手动预览确认。清空结果及日志内容，持续保留精简计费字段和 rowid，避免累计用量、每日上限与 Exa 手动余额变化。空闲 SQLite 页面可复用，未承诺固定磁盘上限；大量 JSON 或 SQLite 操作仍可能短暂占用主线程。当前网页备份有文件、解压和并发限制，大数据量需停机目录备份。
- 备份在内存完成，建议 VPS 至少 2 GiB 内存。密码派生与压缩使用异步系统接口，但大量 JSON 验证和 SQLite 写入仍会占用主线程；恢复属于维护操作。
- 普通 key、官网登录 token 的有效期与供应商侧撤销不受备份控制。目标恢复到旧快照可能包含旧登录状态；必须先停止源实例，必要时重新登录供应商。
